## 二、必须遵守的鸿蒙 UI/UX 原则

### 1. 以鸿蒙官方设计指南为源头

- 设计前先确认目标设备、窗口形态、页面层级、系统特性和官方 UX 标准。
- 涉及控件时优先选用 HarmonyOS / ArkUI / HDS 已定义控件，不自造交互样式。
- 涉及图标时优先使用 HarmonyOS Symbol 或符合官方图标资源规范的图标。
- 涉及色彩时基于 HarmonyOS Token 分层：`brand`、`font_primary`、`font_secondary`、`background_primary`、`comp_background_*`、`interactive_*` 等。
- 涉及字体时默认使用 HarmonyOS Sans，并按展示、标题、子标题、正文、说明五类组织层级。
- 涉及单位时使用 `vp` 和 `fp`；字号要支持系统大字体和无障碍缩放。

### 2. 以全场景多设备为默认前提

- 先保证手机最小屏幕可完整使用，再向折叠屏、平板、电脑等大屏延展。
- 布局默认遵循移动优先、响应式设计、断点系统和栅格系统。
- 窗口宽度 `0 <= vp < 600` 使用 4 Columns，`600 <= vp < 840` 使用 8 Columns，`840 <= vp` 使用 12 Columns。
- 大屏不只是放大手机页面，应使用自适应拉伸、缩放、延伸、隐藏、折行、缩进、挪移、重复、分栏等方法。
- 效率型应用在宽屏优先考虑分栏；浏览型页面可考虑宫格、瀑布流或内容延展。
- 折叠设备要考虑开合连续、悬停态、折痕避让、滚动位置保持和输入内容保持。
- 电脑和平板要考虑鼠标、触控板、键盘、焦点导航、悬浮态、快捷键和窗口响应式。

### 3. 以系统特性适配为必选项

- 状态栏区域背景要保证信息可读，避免左右半区对比过大导致状态栏文字不可读。
- 导航条是 HarmonyOS 典型特征，底部固定控件、底部页签、半模态、弹出框、可滚动页面都要适配导航条。
- 底部导航条区域需要提供沉浸式背景，并考虑 28vp 抬高避让。
- 非一级页面必须有明确返回、关闭或取消路径。
- 全屏沉浸式页面要说明状态栏/导航条隐藏与恢复方式。
- 深色模式不是简单反色，要保持层级一致、语义色一致、控件风格一致，并满足对比度要求。
- 通知、实况窗、服务卡片等系统能力必须按官方规范设计入口、状态和展示内容。

### 4. 以交互可预期和可恢复为底线

- 避免与系统手势冲突，不设计屏幕边缘手势、指关节手势、三指及以上自定义手势作为核心操作。
- 自定义手势不能成为唯一入口；常用功能不能只靠长按触发。
- 点击热区必须满足官方标准：手机/折叠屏/平板主要控件推荐不小于 `48vp x 48vp`，不得小于 `40vp x 40vp`。
- 危险操作必须有确认、影响说明和可恢复策略；删除、重置、停止、取消编辑等使用警示色和二次确认。
- 长任务必须有加载、进度、取消、超时、重试和结果反馈。
- Toast / 即时反馈只用于轻量反馈，不承载复杂交互，不频繁弹出，单次显示不超过 3 秒。
- Dialog 是强打断控件，只用于必须确认或必须关注的信息；一般提示优先使用页面内提示、Banner、Toast 或非模态反馈。

### 5. 以可验收为输出标准

- 每个页面必须有默认、加载、成功、失败、空、无权限、离线、后台恢复等状态。
- 每个关键控件必须说明默认、按下、悬浮、获焦、禁用、加载、选中、错误等状态。
- 每个多端适配结论都要说明触发断点、布局变化、保留内容、隐藏内容和验收方式。
- 每个视觉规范都要能映射到 Token、控件样式、间距、字号、图标和资源。
- 不说“提升体验”“界面简洁”“适配大屏”这种空话，必须说明具体页面、具体组件、具体状态和具体验收条件。

- 强调与品牌使用 `brand` / `background_emphasize` / `comp_background_emphasize`。
- 警示、错误、确认使用语义色，不用品牌色替代危险语义。
- 深色模式使用同名 Token 映射，不手工反色。
- 正文与背景对比度满足官方 UX 标准，深色模式注意舒适性上限。

字体要求：

- 默认 HarmonyOS Sans。
- 手机端按 Display、Title、Subtitle、Body、Caption 分层。
- 正文、列表、按钮、标题栏、说明文本分别给出字号、字重和最大行数。
- 支持系统大字体；放不下时优先换行、折行或布局调整，不优先缩小到不可读。

### 12. 动效与反馈

必须说明：

- 页面层级转场
- 搜索转场
- 新建 / 编辑转场
- 共享元素转场
- 滑动跟手反馈
- 滑动过界反馈
- 离手减速
- 加载动效
- 连接 / 扫描 / 发送 / 同步等任务反馈
- 动效降级策略

原则：

- 优先使用系统转场和 HDS 控件动效。
- 页面层级转场优先左右位移。
- 搜索转场优先共享元素。
- 新建可使用上下位移，编辑可使用淡入淡出。
- 不允许单帧硬切换关键页面。
- 动效服务于空间关系、状态变化和反馈，不做无意义装饰。
- 长任务必须同时有文字说明，不能只靠动画表达。
