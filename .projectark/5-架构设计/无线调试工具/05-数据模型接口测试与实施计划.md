# 数据模型、接口、测试与实施计划

## 1. 目的

本文把无线调试工具的公共领域模型、Repository/UseCase 接口、错误码、存储表、测试策略和开发阶段统一收束，作为后续编码、评审和真机验证的执行基线。

适用范围：

1. 蓝牙模块。
2. WiFi 与网络模块。
3. 星闪模块。
4. 统一日志中心。
5. 统一命令面板。
6. 权限、后台、能力探测、设置。

## 3. 核心领域模型

### 3.1 DebugTarget

```text
DebugTarget
  id: string
  module: ModuleType
  protocol?: ProtocolType
  displayName: string
  address?: string
  addressType?: string
  host?: string
  port?: number
  uuid?: string
  alias?: string
  favorite: boolean
  attributes: Record<string, string | number | boolean>
```

用途：

1. 抽象蓝牙设备、WiFi AP、网络 endpoint、NearLink 设备。
2. 支撑统一收藏和最近访问。
3. 支撑日志中心按目标筛选。

### 3.2 DebugSession

```text
DebugSession
  id: string
  type: SessionType
  module: ModuleType
  protocol: ProtocolType
  target?: DebugTarget
  displayName: string
  mode: expert | light
  state: SessionState
  startAtMs: number
  endAtMs?: number
  result?: SessionResult
  error?: DebugError
  tags: string[]
  attributes: Record<string, string | number | boolean>
```

### 3.3 DebugLogRecord

```text
DebugLogRecord
  id: string
  sessionId: string
  module: ModuleType
  protocol: ProtocolType
  direction: Direction
  recordType: bytes | text | state | error | metric | permission | lifecycle
  timestampMs: number
  payloadRef?: PayloadRef
  payloadSize: number
  summary: string
  displayHint: text | hex | mixed | json | none
  appCode?: string
  nativeCode?: string | number
  attributes: Record<string, string | number | boolean>
```

### 3.4 PayloadRef

```text
PayloadRef
  storageType: inline | file
  inlineBytes?: Uint8Array
  filePath?: string
  offset?: number
  length: number
  sha256?: string
```

规则：

1. 小 payload 可 inline。
2. 大 payload 写文件。
3. 导出时根据 ref 读取原始 bytes。
4. UI 展示只读 payload，不回写。

### 3.5 DebugError

  appCode: string

  userAction?: string
  nativeCode?: string | number
  nativeMessage?: string
  severity: info | warning | error | fatal

  attributes: Record<string, string | number | boolean>

## 9. 实施计划

### 9.1 Phase 0：架构骨架

目标：

1. 建立单 HAP 内目标目录。
2. 建立基础模型。
3. 建立 SessionRuntimeStore。
4. 建立 LogRepository 初版。
5. 建立 PermissionOrchestrator。
6. 建立 CapabilityRegistry。
7. 建立根 Navigation。

验收：

1. App 启动进入工作台。
2. 能创建 fake session。
3. 能写入和查看 fake log。
4. 权限状态可展示。

### 9.2 Phase 1：蓝牙 P0

目标：

1. 经典蓝牙扫描。
2. SPP Client。
3. SPP 终端。
4. BLE 扫描。
5. GATT 基础读写。

验收：

1. SPP 与测试设备收发成功。
2. BLE GATT Notify 可记录日志。
3. 日志可导出。

### 9.3 Phase 2：WiFi/Network P1

目标：

1. WiFi 总览和扫描。
2. 网络诊断。
3. TCP/UDP。
4. HTTP。
5. WebSocket Client。
6. LAN 发现。

验收：

1. TCP/UDP/HTTP/WebSocket 均能产生统一日志。
2. 后台前台恢复状态正确。
3. 端口扫描可取消且不卡 UI。

### 9.4 Phase 3：NearLink P2

目标：

1. NearLink 能力探测。
2. 扫描和广播解析。
3. SSAP Client。
4. dataTransfer。

验收：

1. 支持设备上能完成 SSAP 读写。
2. dataTransfer 能收发并记录日志。
3. 不支持设备上降级清晰。

### 9.5 Phase 4：模块拆 HAR

触发条件：

1. Phase 1-3 至少一个模块稳定。
2. import 边界无循环。
3. 公共底座 API 稳定。

目标：

1. 拆 `common-core`、`common-platform`、`common-storage`、`common-ui`。
2. 拆 `feature-debug-core`。
3. 拆三个协议 feature。
4. 修复 router map 和资源访问。

## 10. 代码评审清单

### 10.1 架构

1. UI 是否直接调用平台 API。
2. ViewModel 是否保存连接真相状态。
3. DataSource 是否有释放路径。
4. feature 之间是否出现横向依赖。
5. common 是否包含业务语义。
6. 错误是否保留 nativeCode。
7. 权限是否按场景申请。

### 10.2 日志

1. 是否保留原始 payload。
2. 是否误把 byte stream chunk 当业务帧。
3. 是否把敏感数据写入 HiLog。
4. 导出是否可选择脱敏。
5. 大 payload 是否走文件。

### 10.3 并发

1. GATT 操作是否串行。
2. 命令发送是否队列化。
3. 端口扫描是否有限并发。
4. 长任务是否可取消。
5. UI 线程是否被阻塞。

### 10.4 后台与生命周期

1. onBackground 是否通知运行会话。
2. onForeground 是否 reconcile 平台真实状态。
3. 后台扫描是否被禁止或明确申请后台策略。
4. socket 中断是否能恢复或提示。
5. 页面退出是否只释放 UI 订阅。
