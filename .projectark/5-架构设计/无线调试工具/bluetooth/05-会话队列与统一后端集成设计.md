# 05 — 会话队列与统一后端集成设计

> **状态**：定稿 · 2026-07-27（v1.1 多会话）  
> **依据**：竞品 SerialService / NUS writeBuffer · `debug_core` · Connectivity Kit socket/ble FAQ  
> **关联**：`02-SPP终端连接收发与日志设计.md` v1.2

---

## 1. 四类独立会话

| Kind | SessionId 前缀 | Transport | 写通道 |
| --- | --- | --- | --- |
| `CLASSIC_SCAN` | `classic-scan` | 无 | 无 |
| `BLE_SCAN` | `ble-scan` | 无 | 无 |
| `SPP` | `spp` | SppTransportSession | CommandWriteQueue → sppWrite* |
| `BLE_GATT` | `gatt` | GattTransportSession | GattOperationQueue |
| `BLE_UART` | `uart` | GattTransportSession（Preset） | CommandWriteQueue → chunk → OpQueue |

扫描类与连接类状态机**禁止混用**。连接前必须 stop 对应扫描。

---

## 2. 生命周期

```text
Preparing → Connecting → Ready ⇄ (Writing|OpQueued)
Ready → Disconnecting → Closed
意外断连 → Reconnecting(policy) → Connecting | Failed
```

铁律：

1. `Closed` 后 Transport **不可复用**（新建实例）。
2. 每个 `on` 必须 `off`；先停读再 close。
3. UI detach ≠ teardown；返回页 Dialog「保持 / 断开」。
4. 断开时 `CommandWriteQueue.reset()` / `GattOperationQueue.clear()`。

---

## 3. 队列拓扑

```text
[终端 Send / 周期发送 / 命令面板]
        │
        ▼
 CommandEncoder (text|hex|base64 + newline)
        │
        ▼
 CommandWriteQueue ──满──▶ reject + UI 状态（不静默丢，除非策略显式 drop-oldest）
        │
        ├── SPP: sppWriteAsync（建议单次 <600B）
        └── UART: GattWriteChunker(mtu-3) → per-session GattOperationQueue

[平台 RX]
 SPP sppRead* / GATT BLECharacteristicChange
        │
        ▼
 RX chunk（边界=transport）
        ├── LogCaptureService（落盘真相）
        └── UI throttle merge（清屏只清 UI）
```

### 3.1 CommandWriteQueue（域服务）

| 属性 | 约定 |
| --- | --- |
| 归属 | 每活跃 SPP/UART 写会话 1 个队列 |
| 背压 | maxDepth 可配；默认拒绝新入队 |
| 与 debug_core | 可挂接 `TransportWriteQueueRegistry`；域队列负责蓝牙策略，Registry 负责跨模块登记 |
| 周期发送 | 最小间隔门控；队列暂停则自动停周期 |

### 3.2 GattOperationQueue

| 属性 | 约定 |
| --- | --- |
| 归属 | **每个** GATT/UART Session 独立 |
| 串行 | R/W/Notify/Indication 上次完成才能下次（Kit 硬约束） |
| 多连接 | 会话间队列互不阻塞；总连接数应用层 ≤4 |

## 4. 与 debug_core 边界

| 组件 | 职责 | 蓝牙模块禁止 |
| --- | --- | --- |
| `SessionRuntimeStore` | 会话摘要、状态、字节计数 | 自建第二套全局会话表 |
| `LogCaptureService` | 原始 chunk 落盘/导出 | UI TextView 当唯一日志 |
| `CommandTemplate` / SendCommand | 跨模块命令模板 | 在 Page 硬编码命令库 |
| `TransportWriteQueueRegistry` | 跨传输登记 | 绕过登记直写 Kit |

蓝牙 Feature **观察** Runtime/Log，**不**在 UI 层持有 socket 句柄。

字节计数：`SessionRuntimeStore.applyPatch({ bytesInDelta / bytesOutDelta })`；读模型用 `getState(sessionId).bytesIn/Out`。

## 5. SPP 多会话 vs GATT 多会话

| 路径 | 策略 |
| --- | --- |
| SPP | `SppSessionLedger` 管理槽位；身份键 `(classicDeviceId, serviceUuid)`；应用层最多 **4** 路并行 Ready/Connecting；同 key 拒绝 `YW-BT-1316`；超限 `YW-BT-1317`；活动列表展示多路摘要；终端以 `focusSessionId` 绑定写端 |
| GATT | 最多 4 个并行 Session；`tryReserveBleConnection` / `releaseBleConnection`；超限映射资源上限错误码 |
| UART | 体验同串口终端；底层仍为 GATT Client，占用 GATT 槽位 |

**已废弃**：SPP「同时仅 1 个 Ready 写端 / SppActiveWritePolicy」。

对称要求：

1. Connect 前 reserve（AdmissionPolicy 与 Ledger 共用 `SppSessionKey` 规范化）；失败/断开必须 release。  
2. 重连不 release key（Ledger `reconnecting`）；FAILED / 耗尽 / 配对丢失必须 release。  
3. 每会话独立写队列与读 loop。  
4. Observe 活动列表，UI 不轮询私有 Map。

---

## 6. Kit 读写硬约束（不可破）

1. 同一 SPP `clientSocket`：`on('sppRead')` 与 `sppReadAsync` **不可混用**。  
2. 关闭顺序：先 off 读（若事件模式），再 `sppCloseClientSocket`。  
3. GATT：先 connect → getServices → 再 R/W/Notify。  
4. 写 Notify 载荷默认 **MTU−3**；MTU 范围 23~517。  
5. 大量写勿堵主线程（taskpool）。  
6. 同设备同 UUID 不可并发（平台 FAQ）。
