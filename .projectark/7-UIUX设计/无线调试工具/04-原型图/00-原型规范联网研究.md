# 原型规范联网研究

> **状态**：2026-07-03 联网检索后重建依据  
> **用途**：约束 `index.html` 的原型画板排布，避免把 APP 原型做成网页 UI

---

## 1. 联网结论

| 来源 | 可执行结论 |
| --- | --- |
| Figma Prototype Guide | 原型要围绕用户旅程组织多个 frame 和 flow，不是单页展示图。 |
| Figma Prototype Flows | 一个原型页可以包含多个 flow starting point，用于测试不同任务路径。 |
| NN/g Mobile & Tablet Reports | 手机和平板需要分别考虑触屏可用性，平板不是手机简单放大。 |
| NN/g Responsive/Adaptive | 小屏、平板、大屏应保留功能一致性，但布局按上下文重排。 |
| HarmonyOS 布局基础与响应式布局 | 原型必须体现 4/8/12 栅格、断点、分栏、挪移、重复布局。 |
| HarmonyOS 间隔参数 | 间距按 4vp/8vp 体系，不使用随意数值。 |

---

## 2. 本原型采用的规范

| 规范 | 应用方式 |
| --- | --- |
| APP 原型载体 | HTML 只是画板，主体是设备 frame，不做网页产品页。 |
| 手机优先 | 手机区使用 390×844 设备框，按单栈任务流排布。 |
| 平板独立 | 平板区使用 1024×768 设备框，按双栏生产力布局重排。 |
| 多 flow | 蓝牙、WiFi、星闪、全局状态分别形成独立 flow。 |
| 完整任务闭环 | 每个 flow 覆盖发现、选择、配置、执行、观察、恢复、导出。 |
| 组件标注 | 每个 frame 显示关键控件、状态和跳转关系。 |
| HarmonyOS 风格 | 使用状态栏、安全区、底部 Tab、侧边导航、Sheet/Dialog、语义色。 |
