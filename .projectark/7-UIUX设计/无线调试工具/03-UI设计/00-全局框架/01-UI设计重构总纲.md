## 2. 被废弃的旧设计问题

旧稿存在以下结构性问题，因此不继续补丁式修改：

| 问题 | 后果 | 新设计处理 |
| --- | --- | --- |
| 页面文档分散，缺少统一任务模型 | 功能有描述但用户流程不闭合 | 建立全局调试闭环和覆盖矩阵 |
| 竞品证据和页面布局混在一起 | 容易照搬竞品而不是使用 HarmonyOS 原生设计 | 竞品只作为能力校验，不作为视觉规范 |
| 模块页面与设置、日志、命令边界不够硬 | 可能重新出现全局日志/命令中心 | 统一规定模块自治和后端统一 |
| 宽屏规则不够可执行 | 容易变成简单拉伸 | 重建手机、双栏、三分栏布局契约 |
| 状态设计散落 | 权限、后台、断连、导出等状态容易漏 | 建立状态矩阵与验收清单 |

## 3. 设计北极星

YoWire 是专业无线调试工具，不是营销型首页，也不是普通设备管理 App。界面必须让用户快速进入调试现场、稳定观察数据、随时恢复错误、可靠保存证据。

核心体验：

```text
发现对象 -> 过滤对象 -> 选择对象 -> 配置连接 -> 建立会话 -> 发送/订阅/诊断
        -> 观察日志 -> 处理异常 -> 保存导出 -> 回到最近会话继续
```

所有模块都必须保留这个闭环。任何控件、页面或弹层如果不服务这个闭环，就不进入 v2 UI。

---

## 4. 页面契约模板

每个页面必须满足以下契约：

| 字段 | 必填内容 |
| --- | --- |
| 页面目标 | 用户进入该页面要完成的调试任务 |
| 入口 | L0 Tab、模块内 Segmented、列表项、最近会话、深链、设置入口 |
| 主体布局 | 手机、600-839vp、840vp 及以上分别如何呈现 |
| 主操作 | 最多 1 个主操作，次操作收敛到工具栏、菜单或 Sheet |
| 状态 | 空态、加载、权限拒绝、能力不可用、执行中、失败、成功、后台运行 |
| 数据回写 | 会话、日志、收藏、命令、过滤器、导出记录如何持久化 |
| 退出 | 返回、断开、保留连接、后台继续、导出前确认 |
| 验收 | 对应覆盖矩阵中的功能 ID |

## 5. 全局导航

| 层级 | 结构 | 说明 |
| --- | --- | --- |
| L0 | 工作台 / 蓝牙 / WiFi / 星闪 / 更多 | 底部 Tab 或侧边 Tab，保持 5 个入口 |
| L1 | 模块首页或模块任务页 | 每个模块自主管理扫描、会话、设置 |
| L2 | 会话详情、终端、GATT 树、SSAP 树、诊断结果 | 承载高频调试 |
| L3 | 写入、过滤、UUID、端口、风险确认 | 使用 Sheet 或 Dialog，不做长期页面 |

禁止：

| 禁止项 | 原因 |
| --- | --- |
| 独立全局日志中心 Tab | 破坏模块上下文 |
| 独立全局命令中心 Tab | 命令依赖协议和会话上下文 |
| 宽屏第四 Inspector | 超出 HarmonyOS 生产力三栏模型 |
| 启动即请求全部权限 | 违背按任务时机请求原则 |

## 6. HarmonyOS 原生化原则

| 领域 | 设计要求 |
| --- | --- |
| 单位 | 全部使用 vp/fp |
| 栅格 | 手机 4 列，600-839vp 8 列，840vp 及以上 12 列 |
| 安全区 | 顶部状态栏、底部导航区、折叠屏铰链区域必须避让 |
| 弹层 | Sheet 处理补充任务，Dialog 只处理高风险阻断，Popup/Menu 处理轻量选择 |
| 焦点 | 平板、PC、键鼠场景必须有可见焦点顺序 |
| 触控 | 关键触控目标不小于 40vp，推荐 48vp |
| 深色模式 | 使用语义 Token，不做简单反色 |
| 无障碍 | 状态不只依赖颜色，日志和图表必须有文本说明 |
