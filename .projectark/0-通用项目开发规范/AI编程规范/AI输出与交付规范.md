# AI输出与交付规范

## 总则

本规范用于统一 AI 完成任务后的结果表达方式。  
AI 的输出必须做到：**说清做了什么、没做什么、改了哪里、有什么限制、下一步需要什么条件**。

---

## 输出基本原则

### 1. 已做与未做必须分开

AI 必须明确区分：

- 已完成的修改
- 已完成的检查
- 未执行的验证
- 需要额外授权才能做的事情

### 2. 事实与判断必须分开

- 事实：已经读取、已经修改、已经创建、已经检查
- 判断：推测可能、建议进一步、理论上可行

不能把判断写成事实。

### 3. 风险与限制必须显式说明

尤其在以下场景中，必须主动说明限制：

- 未编译
- 未运行
- 未执行测试
- 未查看全部调用方
- 用户未授权高风险操作

---

## 标准交付内容

每次完成代码或文档修改后，AI 应尽量给出以下信息：

| 项目 | 说明 |
|------|------|
| 修改文件 | 列出本次修改的文件 |
| 变更内容 | 简述每个文件改了什么 |
| 变更目的 | 说明这些修改是为了解决什么问题 |
| 影响范围 | 指出可能受影响的模块、页面、调用方 |
| 未验证项 | 明确哪些内容尚未编译、运行或测试 |
| 后续建议 | 仅在必要时提出下一步建议 |

---

## 推荐表达方式

建议优先采用以下结构：

1. 先说明结果是否已完成
2. 再列出修改文件
3. 再概括关键变更
4. 再说明限制与未验证项
5. 最后再给必要的下一步建议

---

## 必须明确说明的事项

若以下事项未执行，必须明确写出：

- **未编译项目**
- **未运行项目**
- **未执行测试**
- **未使用 Git 检查差异**
- **未安装依赖或未修改环境**

---

## 禁止事项

- 禁止笼统写“已处理完毕”但不说明改了什么
- 禁止把“理论可行”描述成“已经验证通过”
- 禁止隐瞒高风险操作未获授权这一事实
- 禁止在没有证据时给出绝对化结论
- 禁止使用含糊表述掩盖未验证项
