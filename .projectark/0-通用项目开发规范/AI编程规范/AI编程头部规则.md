# AI编程头部规则

## 总则

本规范用于定义 AI 在任何项目任务开始前都必须默认携带的**头部硬约束**。  
这些规则不依赖具体语言、框架或平台，只要用户未明确授权，AI 就必须先遵守这些边界。

---

## 默认头部规则

### 1. 默认禁止编译项目

未经用户明确允许，AI 不得主动执行：

- 编译
- 构建
- 打包
- 启动应用
- 启动开发服务器
- 执行完整测试任务
- 执行会隐式触发构建、运行或测试的脚本

### 2. 未经允许禁止使用任何 Git 命令

未经用户明确允许，AI 不得主动执行任何 Git 命令，包括但不限于：

- `git status`
- `git diff`
- `git log`
- `git add`
- `git commit`
- `git checkout`
- `git reset`
- `git stash`
- `git pull`
- `git push`
- `git clean`
- `git merge`
- `git rebase`

### 3. 未经允许禁止安装、升级、删除依赖

未经用户明确允许，AI 不得主动执行：

- 依赖安装
- 依赖升级或降级
- 锁文件改动
- 包管理器同步
- 自动修复依赖冲突

### 4. 未经允许禁止执行高破坏性文件操作

未经用户明确允许，AI 不得主动执行：

- 批量删除文件
- 批量重命名文件
- 覆盖式生成大量文件
- 清空缓存、构建目录或中间产物目录
- 大范围移动目录结构

### 5. 未经允许禁止触碰敏感资产与真实环境

未经用户明确允许，AI 不得主动修改：

- 密钥、证书、签名
- 环境变量与环境配置
- 数据库
- 远程服务配置
- 生产、测试或真实业务环境数据

---

## 默认允许的低风险操作

在不触发高风险边界的前提下，AI 默认可以执行：

- 阅读文件与目录结构
- 搜索关键字、引用关系、调用链
- 分析代码、文档、配置与架构
- 修改目标范围内的代码和 Markdown 文档
- 新建完成当前任务所必需的小规模文件
- 输出修改说明、未验证项与后续建议

---

## 头部规则的使用方式

所有 AI 编程任务默认都应先加载本规范中的规则。  
除非用户在当前任务中明确说明“可以编译”“可以使用 Git”“可以安装依赖”等，否则 AI 必须按本规范执行。

---

## 禁止事项

- 禁止把“只是查看一下”作为执行 Git 命令的理由
- 禁止把“为了验证一下”作为默认编译或运行项目的理由
- 禁止把“顺手处理一下”作为安装依赖或改动锁文件的理由
- 禁止在未说明风险的前提下触碰敏感配置与真实环境
