## 信息架构（任务已限定，草图按此画）

一个 App，一个根 `Navigation`，一个 `NavPathStack`。窄屏用栈，宽屏用同一套目的地分栏。返回逐级弹出。没有底部三栏，也没有每个无线模块各自的导航栈。

```text
工作台（导航栏内容）
├── 蓝牙
│   ├── 经典蓝牙 → 配对半模态 → 连接半模态 → SPP 终端
│   └── BLE → GATT → BLE 串口
├── Wi-Fi
│   ├── 环境（AP、信道）
│   ├── 诊断
│   ├── 协议
│   └── 局域网发现
├── 星闪
│   ├── 扫描
│   ├── SSAP
│   └── dataTransfer
├── 命令面板
├── 日志 → 会话详情
└── 设置
```

产品任务（工作台、命令、日志、设置，以及三条无线链路的关键页）决定「有哪些页」。页面内部用列表、宫格还是半模态，草图里标成未选定。

## 技能怎么用的

1. **ui-ux-pro-max**：跑过 design-system 检索。它建议海军蓝 `#1E3A5F`、绿色 CTA 和营销首屏。产品是调试工具，色彩又被宇宙蓝/雪域灰钉死，所以丢掉配色和 Hero 结构，留下对比度 4.5:1、不用表情当图标、底栏不超过五项、表单要有可见标签。
2. **interface-design**：按工具界面来排，不按落地页。每屏一个主动作。首页的重点是最近会话，扫描页的重点是搜索结果，设置页的重点是分组。没有眉题，没有大数字指标墙。
3. **ui-design-brain / baoyu-design**：层次和密度。空态留在内容区。开关只给立刻生效的设置。半模态里不再套半模态。
4. **impeccable**：Operate 模式，过了一遍工艺底线。没有渐变字、左侧色条、阴影加描边、彩虹徽章、表情图标、等权双主按钮。等宽字体只出现在日志和报文。

## 采用的布局

- 蓝牙和星闪扫描：白卡片，圆角 16，行高 76。经典蓝牙和低功耗的「连接」是浅灰胶囊、品牌色字，贴在卡片右侧。页面底部一颗实心胶囊按钮。
- 星闪扫描行内不放连接。随机地址在次行末尾用中性胶囊「随机」。
- 日志：顶栏分类、关键字、一排级别芯片。选中为黑底白字。列表是 48 高的白行和圆点，不是彩色描边卡。
- 空态和权限墙：中部一句说明，能恢复时底部一颗主按钮。不放超过 48vp 的插画，也不在正式页上同时摆三颗演示芯片。
- 连接：底部半模态。第一行标题和关闭，然后字段，底部一颗主按钮。Wi-Fi 是只读 SSID、密码和「下一步」。星闪只在需要端口时出现「端口」和「连接」。
- 测速在诊断的「故障」页：一个页标题字号的速率，下面三列时延、下载、上传，再是通过/失败清单。
