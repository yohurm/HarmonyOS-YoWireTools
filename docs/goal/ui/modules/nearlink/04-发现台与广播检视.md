# 发现台与广播检视

## 总则

发现台先确认过滤契约，再接收广播。结果是广播卡片，不是待配对设备行。广播检视负责原始字节和解析字段，解析失败也不丢弃原始包。

原型：

| 状态 | 文件 |
| --- | --- |
| 过滤契约 | `docs/goal/ui/prototypes/nearlink/05-discovery-filter.svg` |
| 发现进行中 | `docs/goal/ui/prototypes/nearlink/06-discovery-scanning.svg` |
| 广播卡片 | `docs/goal/ui/prototypes/nearlink/07-discovery-results.svg` |
| 无匹配 | `docs/goal/ui/prototypes/nearlink/08-discovery-empty.svg` |
| 空过滤被拒绝 | `docs/goal/ui/prototypes/nearlink/09-discovery-rejected.svg` |
| 广播检视 | `docs/goal/ui/prototypes/nearlink/10-adv-inspect.svg` |

## 发现台区域

标题栏标题为「发现」，可返回工作台。返回时如果仍在扫描，先停止扫描再出栈。标题下有一条能力条，显示开关、权限和当前 API 对空过滤的态度。

页面主体按顺序：

1. 过滤组列表。一组一张卡。组内字段是与，组与组之间是或。
2. 扫描契约。模式三选一：低功耗、均衡、低延迟。时长默认 30 秒，允许 10–60 秒，或单独打开「持续发现」。
3. 主按钮。过滤不合法时禁用，并说明原因。
4. 结果区。只有开始发现之后才出现。空闲时不放一张空设备列表。

### 一组过滤里有什么

平台字段只有：

| 字段 | 规则 |
| --- | --- |
| 设备名 | 可空。轻量路径鼓励先填它，与 Codelab 一致 |
| 地址 | 可空。填的是本轮随机地址，旁边注明不能长期依赖 |
| 厂商 ID | 有厂商数据时必填 |
| 厂商数据 | 十六进制。有掩码时必填 |
| 掩码 | 与厂商数据去掉空白后的长度一致，否则 `YW-NL-1004` |

服务 UUID 和 RSSI 下限不在这张卡里。它们出现在结果区的「只看」后筛，文案写明「这不是平台过滤，只影响当前列表」。

API 不低于 26 时，扫描契约末尾多一个开关「允许无过滤」。打开后出现功耗和噪声说明，用户确认才把 `allowNullFilter` 设为真。API 13 到 25 不显示这个开关。

## 发现交互

开始发现前校验过滤。API 13 且没有任何有效字段时，不调用 `startScan`，页面进入「空过滤被拒绝」，错误码 `YW-NL-1003`。

发现中：

- 能力条改为「模式、已进行秒数 / 总秒数、过滤组数量」。
- 进度表示剩余时长。持续发现没有百分比，改为已运行时间和「停止发现」。
- 每收到一批 `deviceFound`，按本轮键合并：随机地址、服务 UUID 集合、厂商 ID、本地名、时间窗。不把不同时间窗的随机地址收成一台永久设备。
- 主按钮变为「停止发现」。停止中按钮禁用，直到 `stopScan` 结束。

发现结束后保留结果和所用契约，方便原契约再跑一次。

## 广播卡片

一张卡片包含：

- 展示名，以及名称来源：系统名或广播本地名。两者不一致时整张卡用警告底，并同时写出两个名字。
- RSSI。127 显示「RSSI 无效」，不换算距离，对应 `YW-NL-1005`。
- 本轮随机地址。
- 见到次数和最后一次时间。
- 服务数量、厂商 ID、原始字节长度。有解析告警时显示告警数。
- 三个动作：看广播、绑定服务、绑定端口。绑定进入会话绑定页，并带上所选平面作为预选，用户仍能改。

卡片上没有「未配对」和单一连接箭头。

无匹配时说明「没有匹配这组过滤的广播」，并提供「放宽过滤」和「用原契约再发现」。不写「附近没有设备」。

扫描失败保留系统码。`1009700099` 对应 `YW-NL-1099`。失败页保留过滤内容，主按钮回到过滤组。

## 广播检视

从卡片的「看广播」进入。顺序固定：

1. 身份：展示名、随机地址、原始长度、告警数。
2. 解析字段：Local Name 及来源、Discovery Level、Service Data 的 UUID 和数据、厂商 ID 和数据。
3. 原始 HEX。可复制。
4. 告警列表。长度不符的 TLV 标出偏移，整包仍保留。

检视页不发起连接。底部提供「绑定服务」和「绑定端口」，与卡片相同。

## 状态补充

| 状态 | 页面表现 | 可操作 | 不可操作 |
| --- | --- | --- | --- |
| 过滤未完成 | 只显示契约 | 编辑过滤、选择模式和时长 | 开始发现 |
| 校验中 | 主按钮加载 | 无 | 重复开始 |
| 发现中 | 进度、已上报数量、新卡片 | 停止、打开检视 | 修改正在使用的过滤组 |
| 停止中 | 能力条写「正在停止」 | 无 | 再次开始 |
| 结束且有结果 | 广播卡片 | 检视、绑定、再发现 | 无 |
| 结束且为空 | 无匹配说明 | 放宽过滤、再发现 | 绑定 |
| 被拒绝 | 401 / 校验原因 | 回到过滤组 | 开始发现 |
| 开关在发现中被关闭 | 结果保留，能力条变为关闭 | 去系统设置 | 继续发现 |

后台回到前台时，若扫描已被系统停止，结果保留，能力条写明「发现已中断」，不自动重开。

## 验收口径

- API 13 的空过滤不能发出 `startScan`。
- 厂商数据缺 ID、掩码长度不一致时，错误落在对应字段上。
- RSSI 127 的卡片不出现 dBm 数值。
- 系统名和本地名冲突时，两个名字都在。
- 每张卡片都能分开进入服务平面和端口平面。
- 原始 HEX 在解析告警之后仍然完整。
