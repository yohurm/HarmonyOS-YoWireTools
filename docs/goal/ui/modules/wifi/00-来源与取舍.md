# 来源与取舍

## 总则

网络模块的布局来自下面这些来源里**可落地的结构**，不来自旧稿换皮，也不复制任何产品的商标、配色或整页截图。

研读范围分四类：Wi‑Fi / 网络诊断产品的信息结构、HarmonyOS 官方示例与市场组件、ArkUI 分栏与导航、本仓库已经落地的领域模型。

## 和官方能力边界对齐

关联与扫描的界面承诺，跟 `.projectark/5-架构设计/无线调试工具/wifi_network/01-WiFi扫描STA信息与环境分析设计.md` 一致：

- 读 WLAN 需要 `GET_WIFI_INFO`。没有该权限时，链路和空口不可读，诊断仍可针对默认网络。
- 真实 BSSID 依赖 `GET_WIFI_PEERS_MAC`。没有时详情写「掩蔽」，不显示伪造成功的地址。
- `startScan` 前台两分钟最多四次，且需要 `SET_WIFI_INFO`。冷却态展示缓存，并带 `YW-WIFI-1002`。
- `enableWifi` / 连接指定网络还依赖系统或企业权限。普通应用的主按钮是打开系统 WLAN，不是应用内连接。

诊断步骤和 `DiagnosticStepKind` 对齐：网络状态、域名解析、TCP、HTTP。Whois 只作为公网对象的附加说明，不参与局域网认主机。

局域网目标必须通过 `PrivateNetworkGuard`。端口范围默认超过 256 即 `YW-NET-2201`，界面在发起前确认，超过阈值则拒绝而不是靠文案提醒。

## 旧稿里被放弃的结构

旧索引把模块写成：

```text
WiFi Tab
├── L0 工作台：摘要 + 环境分析入口 + 网络调试入口
├── 环境分析：左 AP 列表，右 Rating / 信道 / 时间 / Connection
└── 网络调试：Socket | HTTP | WS | MQTT | LAN | 诊断
```

840vp 线框是「左列表 + 右四子页」。那是把 WiFiAnalyzer 的 Fragment 和 Packet Sender 的协议分段放进 HarmonyOS 分栏，列的职责没有变。

本 Goal 放弃这棵树。变化见 [01-信息架构](./01-信息架构.md) 的对照表。
