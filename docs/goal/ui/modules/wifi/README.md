# 网络模块 UI Goal

## 总则

本文是 YoWireTools **网络 / Wi‑Fi 模块**的界面目标。它只定义该模块内部的页面、状态、宽屏分栏和连接流。工作台、蓝牙、星闪的信息架构与页面不在本文范围，也不因本文改动。

旧网络稿作废。作废对象是 2026-07 已删除的 `.projectark/7-UIUX设计/无线调试工具/01-功能清单/03-WiFi模块/` 及其指向的「环境四子页 + 协议分段 + 840vp 子页贴进右栏」。本文按对象重新组织，不沿用那套页面树换颜色。

当前工程里的 `WifiFeaturePage` 仍是空壳。本文不改 ArkUI 实现，只给后续实现可验收的页面目标。领域行为以现有模型为准：`WifiScanPhase`、`WifiAccessPointSnapshot`、`NetworkDiagnosticPlan`、`PrivateNetworkGuard`、`WifiNetworkErrorCodes`。

## 文档规范

本目录遵循项目文档规范 `.projectark/0-通用项目开发规范/0.2-文档规范.md`：中文 Markdown，先写是什么、为什么、怎么组织；流程用 Mermaid，单图节点不超过 10 个；不写排期、人员、测试计划。

页面结构遵循 `.projectark/4-专家模型/HarmonyOS UIUX设计师.md` 的输出要求：信息架构、页面树、断点、控件、状态、文案、UX 对齐。公开的 yoagent 文档描述的是代理循环，不提供界面稿格式；本 Goal 以上述两份项目文档为写作依据。

## 新结构一句话

网络模块里只有四类对象：**链路、接入点、局域网主机、协议会话**。诊断图、详情和连接流都挂在对象上，而不是挂在工具图标上。

## 不做什么

- 不改应用底部页签、工作台首页、蓝牙模块、星闪模块。
- 不把 Ping、DNS、Trace、Whois、Socket、HTTP、WebSocket、MQTT 做成一排入口。
- 不把「连接 WLAN」做成应用内密码表单。普通应用走系统 WLAN 交接；没有相应能力时说明原因。
- 不把信道评分做成与列表、信道图并列的第四个主视图。
- 不把局域网扫描扩展到公网地址。`PrivateNetworkGuard` 拒绝非私网目标。
