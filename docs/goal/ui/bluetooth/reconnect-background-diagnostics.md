# 回连、后台与诊断

路由 `/bluetooth/diagnostics`。从概览或客户端的菜单进入。`MODULE`。状态在 `features/bluetooth` 的诊断与回连 ViewModel。连接、停扫和长时任务都经 `common/yobluetooth` 与 `common/platform`，不经 Kit。

免配对地址固化不在本页画成功，书签规则在 [地址与身份](address-identity.md) 的 BT-030。

## 结构

`YoPageShell` 标题「诊断」。三个线性段落，间距 16vp：

1. 回连。目标地址一行（虚拟地址，等宽）。开关「自动回连」用系统 `Toggle`，样式只取 `YoColor`。失败次数、最近原因、主按钮「停止自动回连」。
2. 后台。开关「退到后台时保持连接」。说明需要 `KEEP_BACKGROUND_RUNNING`，并且 `backgroundModes` 含蓝牙交互。未申请时长时任务的结果说明单独一行。
3. 诊断。最近的平台码列表，每行时间、码、用户句。固定收录：2900001、2900011、2900099 及其子原因。空时用 `YoEmpty`。

`≥600vp`：左栏回连与后台，右栏诊断码。列宽 ≥280vp。

## 信息密度

回连卡片同时可见：次数、最近原因、是否还会再试。不隐藏失败去显示「正在恢复」。

后台只区分两句，用胶囊：

- 「未申请长时任务」`warning`
- 「蓝牙交互任务运行中」`info`

不把任务运行写成「连接一定还在」。连接是否还在看会话胶囊，任务是否在跑看这一枚。

诊断行默认展示码和一句原因。子原因（扫描中禁止连接、GATT 客户端未销毁）作为该行第二句，不缩成「操作失败」。

重复进入页面不会让同一状态变化刷出多行。列表按一次状态变化一行（BT-096）。

## 控件

| 区域 | 符号 |
| --- | --- |
| 停止回连、重新发现 | `YoActionButton` |
| 自动回连、后台保持 | 系统 `Toggle`，旁边 `Text` |
| 任务与回连相位 | `YoStatusPill` |
| 次数 | `YoTypeStyle.TITLE_S` |
| 无诊断事件 | `YoEmpty` |
| 服务停止 | `YoError` 放在列表顶 |
| 频繁操作 | 按钮禁用加 `YoToast` |

## 状态

| 状态 | 本屏 |
| --- | --- |
| 默认 | 自动回连关闭。失败次数 0。后台开关关闭，胶囊「未申请长时任务」。诊断列表若本次进程已有事件则列出，否则为空态 |
| 按下 | 开关按下松手后才改变意图。「停止自动回连」松手后不再发起。「重新发现」松手后进入经典发现或 BLE 扫描，由地址来源决定 |
| 禁用 | 扫描仍在进行时，回连按钮禁用，原因「先停止扫描再连接」；若已经返回「扫描期间不允许连接」，该句成为原因（BT-093）。2900011 时相关按钮暂时禁用，原因「操作频繁」（BT-097）。没有可回连地址时自动回连禁用，原因「需要先发现或配对」 |
| 空 | 本进程还没有任何诊断事件：`YoEmpty`「还没有诊断记录」。回连失败次数不为 0 时不用空态盖住次数 |
| 错误 | 每次自动回连失败增加次数并保留原因，用户能停止（BT-092）。同一设备重连仍用旧客户端导致 2900099 时，子原因写「客户端未销毁」（BT-091）。未申请长时任务就退后台导致断开：原因是应用被挂起，不写「对端主动断开」（BT-094）。2900001：扫描与连接都结束，顶栏 `YoError`「蓝牙服务已停止」（BT-098） |
| 加载 | 一次回连尝试进行中：胶囊「回连中」，次数尚不增加，失败事件到达后才加一。长时任务申请未返回时，后台开关 `loading` 态由旁边按钮的 `loading` 表示，胶囊仍是申请前的句子 |

后台保持打开且已授权、GATT 或 SPP 已连接时，胶囊改为「蓝牙交互任务运行中」（BT-095）。用户停止保持或会话断开后，胶囊回到「未申请长时任务」。本设计不把该胶囊标成 `success`，因为实现阶段仍要真机复验；语气用 `info`。

## 导航

「重新发现」到 `/bluetooth/spp` 或 `/bluetooth/ble`，并带上失效地址的说明，不自动对失效地址再试（与 BT-031 一致）。返回概览或客户端。诊断页不出现在星闪或 Wi‑Fi 的路由表里。

## 非目标

- 不在失败时继续无次数上限地重试且不给停止。
- 不把重复订阅造成的多次回调画成多条相同诊断。
- 不把免配对固化放进本页的成功开关。
