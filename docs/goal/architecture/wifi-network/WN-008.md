# WN-008 未授予对端 MAC 时显示随机地址

## 1. 条目与非目标

清单 `WN-008`，主标记「受限」。行为只取 `docs/goal/research/wifi-network.md` 与 `docs/goal/checklist/wifi-network.md`，不重开行业调查。

- Given：未授予 GET_WIFI_PEERS_MAC
- When：查看扫描行与已连接 BSSID
- Then：地址类型为随机设备地址，或界面标明随机地址

本条输入是 扫描行或已连接 BSSID，且 GET_WIFI_PEERS_MAC 未授予。输出是 系统返回的随机地址，或文案「随机地址」。失败是 星号占位、厂商 OUI 或真实 BSSID 被当成已获得。归属是 WifiInfoDataSource 原样传递系统地址，领域模型用地址种类，页面状态负责文案。

本组「权限与能力」的共用架构图在 [WN-001](WN-001.md)。该链接不代替本条的输入、输出、失败和归属。

本条是受限、系统或企业能力。本安装包没有对应授权时，成功结果是可见拒绝。不出现该权限才会有的成功数据。`product/phone` 的 `module.json5` 与 `common/platform` 的 `AppPermission` 当前没有把这项受限或系统权限当成已授予能力。

设计前 WifiAccessPointSnapshot.maskedBssid 在无权限时返回星号。设计后删除该占位，改为传递系统地址并标明种类。

非目标：不查询厂商。不因为 module.json5 声明了该项就显示真实 MAC。声明不是授予。不把 WLAN 或网络行为放进 `features/bluetooth` 或 `features/nearlink`。不新增包装层、兼容层或版本适配包。本阶段不写产品代码，也不做界面实现。

## 2. 模块边界与分层

设计前：`product/phone` 还没有本条的独立路由。`features/wifi_network` 的 `ui/page/WifiFeaturePage` 是空壳，只组合 `common/youi_kit` 的 `YoPageShell`。Kit 调用已经落在既有数据源，订阅落在 `data/kit/NetworkKitEventBridge`。`WifiNetworkRepository` 直接 import `@kit.NetworkKit`，这条 import 是越层，设计后删除，而不是再包一层门面。页面状态目录尚未接上本条。

设计后：`product/phone` 只做进入与 `module.json5` 声明。页面只订阅页面状态。页面状态只调用 `StartWifiScanUseCase 与 ObserveWifiStateUseCase`。用例只依赖 `WifiNetworkRepositoryContract` 与领域纯函数。副作用停在 `data/datasource/WifiInfoDataSource 的 getScanInfoList 与 getLinkedInfo`。系统接口是 `WifiScanInfo.bssid、WifiLinkedInfo.bssid`。会话行只进 `common/debug_core` 的 `LogCaptureService`，再由 `common/storage` 的 `LogRepository` 落库。进程诊断用 `common/yolog`。取消、时钟与 `Result` 用 `common/core`。权限场景与前后台用 `common/platform`。`common/youi_kit` 不解释 WLAN。

| 步骤 | 归属 |
| --- | --- |
| 进入与权限声明 | product/phone |
| 展示 | features/wifi_network 的 ui/page |
| 页面状态 | features/wifi_network 页面状态（工程目录 viewmodel，对照鸿蒙类型包即页面状态层） |
| 用例与纯规则 | features/wifi_network domain：地址种类：随机、空、可见。替换 WifiAccessPointSnapshot.maskedBssid 的星号分支，不另加掩码适配器 |
| 调用点 | features/wifi_network data/datasource/WifiInfoDataSource 的 getScanInfoList 与 getLinkedInfo |
| 事件订阅 | features/wifi_network data/kit/NetworkKitEventBridge，不再外包一层 |
| 权限场景与前后台 | common/platform PermissionOrchestrator、LifecycleCoordinator |
| 会话日志 | common/debug_core LogCaptureService、DebugLogRecord |
| 落库与导出 | common/storage LogRepository、ExportFileWriter |
| 进程日志 | common/yolog YoLog |
| 结果、取消、时钟 | common/core Result、CancellationToken、TimeUtil |
| 通用页面壳 | common/youi_kit 的 YoPageShell，不承载本条规则 |

依赖方向：`product/phone` → `features/wifi_network` 页面 → 页面状态 → `domain` → `data` → 系统 Kit。`data` 不引用页面。`common/debug_core` 不反向依赖 `features/wifi_network` 的页面。

## 5. 数据模型

领域模型与传输字段分开。页面不直接持有 Kit 结构体。持久化用 `common/storage` 已有的会话与日志记录，不把领域快照原样写进另一层。

| 字段 | 含义 | 所在层 |
| --- | --- | --- |
| `本条输入` | 扫描行或已连接 BSSID，且 GET_WIFI_PEERS_MAC 未授予 | 页面状态收到的事实，不是 Kit 对象 |
| `本条输出` | 系统返回的随机地址，或文案「随机地址」 | features/wifi_network 页面状态 |
| `失败` | 星号占位、厂商 OUI 或真实 BSSID 被当成已获得 | 不得当作成功的结果 |
| `动作` | showBssid | 交给 common/debug_core 的动作名 |
| `终态` | randomAddress | common/debug_core DebugLogRecord |
| `系统接口` | WifiScanInfo.bssid、WifiLinkedInfo.bssid | 只在调用点 data/datasource/WifiInfoDataSource 的 getScanInfoList 与 getLinkedInfo 可见 |
| `授权` | 本安装包未持有成功所需权限 | common/platform 的判断，不产生成功载荷 |

错误只带类别与系统码。`ResultError.nativeCode` 保存 201、801、2501000 这类数字。类别放在 `features/wifi_network` 已有的 `WifiNetworkErrorCodes`。用户可见的一句说明只在页面状态生成，不写进 `common/core` 的错误类型。

## 6. 层间接口

- 页面把用户动作交给页面状态，页面状态不接收 `WifiScanInfo.bssid、WifiLinkedInfo.bssid` 的 Kit 对象。
- 页面状态调用 `StartWifiScanUseCase 与 ObserveWifiStateUseCase`，返回 `common/core` 的 `Result` 或本条领域快照。
- `StartWifiScanUseCase 与 ObserveWifiStateUseCase` 只依赖 `WifiNetworkRepositoryContract` 与领域纯函数，不 import `@kit.ConnectivityKit` 或 `@kit.NetworkKit`。
- `data/datasource/WifiInfoDataSource 的 getScanInfoList 与 getLinkedInfo` 是系统调用点。版本判断与 `BusinessError.code` 分类写在这个调用旁边。
- 会话终态由页面状态交给 `common/debug_core` 的 `LogCaptureService.captureEvent`，`ModuleType` 为 `WIFI`。
- `features/bluetooth` 与 `features/nearlink` 没有本条接口。
- bssidVisible 为 false 时，导出文件同样不写真实地址。

契约落在已有边界：页面状态对用例、用例对 `WifiNetworkRepositoryContract`、数据源对 Kit。`Index.ets` 继续只导出用例、模型与仓库，不在入口文件里写扫描、过滤或套接字算法。

## 7. 权限与生命周期

ohos.permission.GET_WIFI_PEERS_MAC 为受限权限。未授予时没有真实地址成功路径。

地址种类随每次快照更新，不把上一次真实地址留在内存里给未授权会话使用。

本条不建立成功方向的 Kit 订阅，也没有要释放的成功会话。同一页上其他能力若已订阅，仍由 `NetworkKitEventBridge` 成对取消。`WifiSettingsNavigator` 只打开系统设置，不把跳转记成本条成功。

## 8. 日志

成功或失败都写一行会话日志：时间、动作 `showBssid`、终态 `randomAddress`。格式化可走已有的 `WifiScanLogger`、`WifiMessageLogger` 或 `HttpNetworkLogger`，它们只负责组 `DebugEvent` 并调用 `LogCaptureService`，不另建日志库。`common/yolog` 记调用点与系统码，不记密钥、证书私钥或预共享密钥明文。导出走 `common/storage` 的 `LogExportService` / `ExportFileWriter` 时沿用同一掩码。

## 9. 反模式

- 不把权限声明写成已经授予。未获授权时不展示成功数据。
- 不调用仅系统应用、企业应用或受限 ACL 才能成功的接口来制造本条的通过。
- 不用 **:**:**:**:**:** 代替系统随机地址。
- 不在 `WifiNetworkRepository` 上再包一个兼容仓库，也不把版本判断挪到新的适配类。
- 不用空列表、无限加载或占位 MAC 表示本条的失败。
- 不让 `features/bluetooth` 或 `features/nearlink` 订阅 WLAN、默认网络或本应用套接字。
