# WN-019 首次扫描成功后列出缓存中的 AP

## 1. 条目与非目标

清单 `WN-019`，主标记「普通应用」。行为只取 `docs/goal/research/wifi-network.md` 与 `docs/goal/checklist/wifi-network.md`，不重开行业调查。

- Given：WLAN 已打开且位于前台
- When：第一次点击扫描并等到 wifiScanStateChange 为 1
- Then：列表来自随后的 getScanInfoList，每行至少有 SSID、加密类型、RSSI（dBm）、频率、带宽

本条输入是 前台第一次 startScan，以及随后的成功回调 1。输出是 来自 getScanInfoList 的行：SSID、加密类型、RSSI dBm、频率、带宽，并带缓存时间。失败是 回调为 0，或在回调前就把旧列表标成新扫描。归属是 StartWifiScanUseCase 编排；WifiInfoDataSource 调用 startScan 与 getScanInfoList；订阅在 NetworkKitEventBridge。

本组「扫描、过滤与信道」的共用图放在本文件。同组其他条目仍各自写输入、输出、失败和归属。

扫描以 API 参考为准：`startScan`（API 21，权限 `SET_WIFI_INFO`）完成后看 `wifiScanStateChange`（0 失败，1 成功），列表来自随后的 `getScanInfoList`。该接口是当前时刻前 30 秒的缓存，不是一次新扫描的返回值本身。指南里「主动扫描仅系统应用」与 API 参考冲突，本设计不采用指南的那一句。指南里的连接过程中禁扫、WLAN 关闭不扫、温度与静止管控仍是失败路径。界面同时给出缓存时间，以及由 `WifiScanCooldownTracker` 计算的剩余冷却。废弃的 `scan` / `getScanResults` 不进入这条链路，也不把 Android 位置弹窗搬过来。

本条是扫描组的共用图所在。冷却与缓存的规则见 WifiScanCooldownTracker 与 WifiScanSource.CACHE。

非目标：不在点击扫描时同时发起连接。不使用已废弃的 scan 与 getScanResults。不把 WLAN 或网络行为放进 `features/bluetooth` 或 `features/nearlink`。不新增包装层、兼容层或版本适配包。本阶段不写产品代码，也不做界面实现。

## 2. 模块边界与分层

设计前：`product/phone` 还没有本条的独立路由。`features/wifi_network` 的 `ui/page/WifiFeaturePage` 是空壳，只组合 `common/youi_kit` 的 `YoPageShell`。Kit 调用已经落在既有数据源，订阅落在 `data/kit/NetworkKitEventBridge`。`WifiNetworkRepository` 直接 import `@kit.NetworkKit`，这条 import 是越层，设计后删除，而不是再包一层门面。页面状态目录尚未接上本条。

设计后：`product/phone` 只做进入与 `module.json5` 声明。页面只订阅页面状态。页面状态只调用 `StartWifiScanUseCase`。用例只依赖 `WifiNetworkRepositoryContract` 与领域纯函数。副作用停在 `data/datasource/WifiInfoDataSource，订阅在 NetworkKitEventBridge`。系统接口是 `wifiManager.startScan，wifiScanStateChange，getScanInfoList`。会话行只进 `common/debug_core` 的 `LogCaptureService`，再由 `common/storage` 的 `LogRepository` 落库。进程诊断用 `common/yolog`。取消、时钟与 `Result` 用 `common/core`。权限场景与前后台用 `common/platform`。`common/youi_kit` 不解释 WLAN。

| 步骤 | 归属 |
| --- | --- |
| 进入与权限声明 | product/phone |
| 展示 | features/wifi_network 的 ui/page |
| 页面状态 | features/wifi_network 页面状态（工程目录 viewmodel，对照鸿蒙类型包即页面状态层） |
| 用例与纯规则 | features/wifi_network domain：WifiAccessPointSnapshot 与 WifiScanSource.ACTIVE_SCAN；缓存时间来自本次读取 |
| 调用点 | features/wifi_network data/datasource/WifiInfoDataSource，订阅在 NetworkKitEventBridge |
| 事件订阅 | features/wifi_network data/kit/NetworkKitEventBridge，不再外包一层 |
| 权限场景与前后台 | common/platform PermissionOrchestrator、LifecycleCoordinator |
| 会话日志 | common/debug_core LogCaptureService、DebugLogRecord |
| 落库与导出 | common/storage LogRepository、ExportFileWriter |
| 进程日志 | common/yolog YoLog |
| 结果、取消、时钟 | common/core Result、CancellationToken、TimeUtil |
| 通用页面壳 | common/youi_kit 的 YoPageShell，不承载本条规则 |

依赖方向：`product/phone` → `features/wifi_network` 页面 → 页面状态 → `domain` → `data` → 系统 Kit。`data` 不引用页面。`common/debug_core` 不反向依赖 `features/wifi_network` 的页面。

## 5. 数据模型

领域模型与传输字段分开。页面不直接持有 Kit 结构体。持久化用 `common/storage` 已有的会话与日志记录，不把领域快照原样写进另一层。

| 字段 | 含义 | 所在层 |
| --- | --- | --- |
| `本条输入` | 前台第一次 startScan，以及随后的成功回调 1 | 页面状态收到的事实，不是 Kit 对象 |
| `本条输出` | 来自 getScanInfoList 的行：SSID、加密类型、RSSI dBm、频率、带宽，并带缓存时间 | features/wifi_network 页面状态 |
| `失败` | 回调为 0，或在回调前就把旧列表标成新扫描 | 不得当作成功的结果 |
| `动作` | startScan | 交给 common/debug_core 的动作名 |
| `终态` | success | common/debug_core DebugLogRecord |
| `系统接口` | wifiManager.startScan，wifiScanStateChange，getScanInfoList | 只在调用点 data/datasource/WifiInfoDataSource，订阅在 NetworkKitEventBridge 可见 |
| `领域归属` | WifiAccessPointSnapshot 与 WifiScanSource.ACTIVE_SCAN；缓存时间来自本次读取 | features/wifi_network domain |

错误只带类别与系统码。`ResultError.nativeCode` 保存 201、801、2501000 这类数字。类别放在 `features/wifi_network` 已有的 `WifiNetworkErrorCodes`。用户可见的一句说明只在页面状态生成，不写进 `common/core` 的错误类型。

## 6. 层间接口

- 页面把用户动作交给页面状态，页面状态不接收 `wifiManager.startScan，wifiScanStateChange，getScanInfoList` 的 Kit 对象。
- 页面状态调用 `StartWifiScanUseCase`，返回 `common/core` 的 `Result` 或本条领域快照。
- `StartWifiScanUseCase` 只依赖 `WifiNetworkRepositoryContract` 与领域纯函数，不 import `@kit.ConnectivityKit` 或 `@kit.NetworkKit`。
- `data/datasource/WifiInfoDataSource，订阅在 NetworkKitEventBridge` 是系统调用点。版本判断与 `BusinessError.code` 分类写在这个调用旁边。
- 会话终态由页面状态交给 `common/debug_core` 的 `LogCaptureService.captureEvent`，`ModuleType` 为 `WIFI`。
- `features/bluetooth` 与 `features/nearlink` 没有本条接口。
- getScanInfoList 的结果始终带缓存时间，即使它紧跟成功回调。

契约落在已有边界：页面状态对用例、用例对 `WifiNetworkRepositoryContract`、数据源对 Kit。`Index.ets` 继续只导出用例、模型与仓库，不在入口文件里写扫描、过滤或套接字算法。

## 7. 权限与生命周期

SET_WIFI_INFO 用于 startScan，GET_WIFI_INFO 用于读列表。都不弹运行时窗。

前台才发起。回调到达或失败后结束本次 ACTIVE_SCANNING。离开页面取消 wifiScanStateChange。

需要订阅的事件在进入时登记，离开时经 `NetworkKitEventBridge` 成对取消。套接字由 `common/debug_core` 的 `SessionManager` 与已有 transport coordinator 释放，页面销毁不直接 `close` Kit 对象。前后台由 `common/platform` 的 `LifecycleCoordinator` 通知用例。

## 8. 日志

成功或失败都写一行会话日志：时间、动作 `startScan`、终态 `success`。格式化可走已有的 `WifiScanLogger`、`WifiMessageLogger` 或 `HttpNetworkLogger`，它们只负责组 `DebugEvent` 并调用 `LogCaptureService`，不另建日志库。`common/yolog` 记调用点与系统码，不记密钥、证书私钥或预共享密钥明文。导出走 `common/storage` 的 `LogExportService` / `ExportFileWriter` 时沿用同一掩码。

## 9. 反模式

- 不把缓存刷新写成一次新的主动扫描，除非本条的 When 确实调用了 `startScan` 且回调为成功。
- 不在页面或 `common/youi_kit` 里直接调用 `wifiManager`、`connection`、`http` 或 `socket`。
- 不按扫描指南把 startScan 拒绝成仅系统应用。
- 不在 `WifiNetworkRepository` 上再包一个兼容仓库，也不把版本判断挪到新的适配类。
- 不用空列表、无限加载或占位 MAC 表示本条的失败。
- 不让 `features/bluetooth` 或 `features/nearlink` 订阅 WLAN、默认网络或本应用套接字。
