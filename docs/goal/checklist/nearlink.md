# 星闪调试能力清单

每条只判定一个结果。证据是界面文案、入口状态、日志记录或错误码。做不到官方 API 的条目，通过标准是界面标明缺口并且不出现成功态。

版本门槛以研究文档为准。低于门槛的系统上，对应条目的通过标准改为显示「当前系统版本不提供该能力」及起始版本，而不是调用未公开参数。

## 设备与开关

### NL-001 支持查询为真

- 前置：系统不低于 6.1.0(23)，`isNearLinkSupported()` 为 true。
- 动作：进入星闪模块。
- 结果：首屏显示当前设备支持星闪。
- 证据：支持状态文案。

### NL-002 支持查询为假

- 前置：`isNearLinkSupported()` 为 false。
- 动作：进入星闪模块。
- 结果：首屏显示当前设备不支持星闪，扫描、广播、连接入口不可用。
- 证据：不可用文案与入口禁用。

### NL-003 低版本以 801 表示不支持

- 前置：系统低于 6.1.0(23)，调用星闪接口返回 801。
- 动作：进入星闪模块并触发一次能力调用。
- 结果：显示不支持，不把 801 显示成开关关闭。
- 证据：错误码 801 与文案。

### NL-004 模拟器不可用

- 前置：运行在模拟器。
- 动作：进入星闪模块。
- 结果：显示需要真机，不出现空的扫描列表当作正常结果。
- 证据：真机提示文案。

### NL-005 开关已打开

- 前置：`getState()` 为 `STATE_ON`。
- 动作：查看能力状态。
- 结果：显示星闪已打开。
- 证据：状态文案。

### NL-006 开关已关闭

- 前置：`getState()` 为 `STATE_OFF`。
- 动作：尝试扫描。
- 结果：扫描不启动，显示星闪已关闭，并给出打开星闪的设置路径说明。
- 证据：未出现 `deviceFound`，可见关闭文案。

### NL-007 正在打开与正在关闭

- 前置：状态变为 `STATE_TURNING_ON` 或 `STATE_TURNING_OFF`。
- 动作：停留在能力状态区。
- 结果：分别显示正在打开、正在关闭，此期间扫描入口不可用。
- 证据：过渡文案。

### NL-008 订阅开关变化

- 前置：已订阅 `stateChange`。
- 动作：在系统设置中打开或关闭星闪。
- 结果：界面状态与最新回调一致，并写一条状态日志。
- 证据：日志中的状态值。

### NL-009 离开页面取消开关订阅

- 前置：已订阅 `stateChange`。
- 动作：离开星闪模块。
- 结果：再次拨动系统开关时，该页面不再收到回调。
- 证据：离开后的日志不再新增该订阅记录。

### NL-010 本机名称

- 前置：星闪已打开且已授权。
- 动作：查看本机身份。
- 结果：显示 `getLocalName()` 的文本，长度不超过 30。
- 证据：名称文案。

### NL-011 本机名称在开关关闭时失败

- 前置：星闪关闭。
- 动作：读取本机名称。
- 结果：显示 `1009700003`，不显示空白名称当作成功。
- 证据：错误码日志。

### NL-012 应用不能打开星闪开关

- 前置：星闪关闭。
- 动作：在模块内查找打开星闪的控件。
- 结果：没有调用任何写开关的接口；只提供前往系统设置的说明。
- 证据：界面无「已打开」成功态，除非用户在设置里打开后 `stateChange` 到来。

## 权限

### NL-013 首次扫描才申请权限

- 前置：未授权 `ACCESS_NEARLINK`。
- 动作：只进入模块、不开始扫描或连接。
- 结果：不弹出授权。用户点击扫描后才申请。
- 证据：进入时无授权弹窗，点击扫描后出现系统授权。

### NL-014 授权后扫描可启动

- 前置：用户同意授权，星闪已打开，过滤条件非空。
- 动作：开始扫描。
- 结果：扫描进入进行中，不返回 201。
- 证据：进行中状态。

### NL-015 拒绝授权

- 前置：用户拒绝授权。
- 动作：再次点击扫描。
- 结果：显示未授权，扫描不启动。提供再次申请。
- 证据：201 或授权拒绝记录，列表无新设备。

### NL-016 永久拒绝后的去设置

- 前置：系统不再弹出授权框。
- 动作：点击扫描。
- 结果：显示需在系统设置中允许星闪权限，并提供前往应用设置的入口。
- 证据：设置入口可见，扫描未启动。

### NL-017 不捆绑蓝牙权限

- 前置：仅进行星闪扫描。
- 动作：观察本次授权请求的权限名。
- 结果：请求列表包含 `ohos.permission.ACCESS_NEARLINK`，不包含 `ACCESS_BLUETOOTH`。
- 证据：授权记录中的权限名。

### NL-018 配置文件已声明权限

- 前置：安装包。
- 动作：检查星闪模块的权限声明。
- 结果：声明了 `ohos.permission.ACCESS_NEARLINK`，并带有用途说明。
- 证据：模块权限声明与用途字符串。

## 扫描与过滤

### NL-019 非空名称过滤能启动

- 前置：已授权，星闪打开，过滤组仅含非空 `deviceName`。
- 动作：开始扫描。
- 结果：扫描成功启动。
- 证据：进行中状态，且无 401。

### NL-020 多过滤组为或

- 前置：两组过滤，一组只有地址 A，一组只有名称 B。
- 动作：开始扫描。
- 结果：地址为 A 或名称为 B 的设备都可以出现；两组条件不是同时满足才出现。
- 证据：只满足其中一组的设备仍出现在列表。

### NL-021 组内字段为与

- 前置：同一组同时填写地址 A 与名称 B。
- 动作：开始扫描。
- 结果：只显示地址为 A 且名称为 B 的设备。
- 证据：只满足一项的设备不在列表中。

### NL-022 5.0.1 全空过滤被拒绝

- 前置：目标系统低于 26.0.0，所有过滤字段为空。
- 动作：开始扫描。
- 结果：不启动扫描，显示需要至少一项过滤条件，日志含 401。
- 证据：401 与未进入进行中。

### NL-023 26.0.0 允许空过滤并提示功耗

- 前置：系统不低于 26.0.0，用户明确选择扫描全部可见设备。
- 动作：以 `filters = null` 开始扫描。
- 结果：扫描可以启动，同时显示可能扫到非预期设备并增加功耗。
- 证据：提示文案与进行中状态。

### NL-024 空过滤在低版本不传 null

- 前置：系统低于 26.0.0。
- 动作：用户选择扫描全部。
- 结果：显示该系统版本不能空过滤，不调用 `startScan(null)`。
- 证据：版本说明文案，日志无该调用的成功记录。

### NL-025 停止扫描

- 前置：扫描进行中。
- 动作：点击停止。
- 结果：状态变为已停止，之后新的广播不再追加到列表。
- 证据：停止后的发现时间不再更新。

### NL-026 重复开始扫描

- 前置：已经在扫描。
- 动作：再次点击开始。
- 结果：不叠两套 `deviceFound` 订阅；列表仍是一份。
- 证据：同一地址在一次回调窗口内只更新一行。

### NL-027 离开页面停止扫描

- 前置：扫描进行中。
- 动作：离开星闪扫描页。
- 结果：已调用停止扫描并取消 `deviceFound`。
- 证据：停止日志。

### NL-028 扫描模式只有两种

- 前置：打开扫描选项。
- 动作：查看可选模式。
- 结果：只有低功耗与均衡。默认是低功耗。没有低时延选项。
- 证据：选项列表。

### NL-029 时长合法范围

- 前置：填写时长 10 秒或 60 秒。
- 动作：开始扫描。
- 结果：到达时长后扫描结束并写日志。
- 证据：结束日志中的时长。

### NL-030 时长越界

- 前置：填写 9 秒或 61 秒。
- 动作：开始扫描。
- 结果：不启动，提示时长取值 [10, 60] 秒；不填时长才是全时段扫描。
- 证据：校验文案，无进行中状态。

### NL-031 厂商数据必须带厂商 ID

- 前置：填写了厂商数据，厂商 ID 为空。
- 动作：开始扫描。
- 结果：不启动，提示需同时填写厂商 ID。
- 证据：校验文案。

### NL-032 厂商掩码长度必须一致

- 前置：厂商数据与掩码的字节长度不同。
- 动作：开始扫描。
- 结果：不启动，提示长度必须一致。
- 证据：校验文案。

### NL-033 厂商 ID 范围

- 前置：厂商 ID 为 0 或大于 65535。
- 动作：开始扫描。
- 结果：不启动，提示取值 [1, 65535]。
- 证据：校验文案。

### NL-034 RSSI 门限版本

- 前置：系统低于 26.0.0，用户设置 RSSI 门限。
- 动作：开始扫描。
- 结果：门限不写入 `ScanFilters`。列表仍显示全部上报，并由本地后滤标出低于门限的行，或明确说明门限仅在 26.0.0 起由系统过滤。
- 证据：界面说明当前门限是本地后滤还是系统过滤。

### NL-035 RSSI 门限系统过滤

- 前置：系统不低于 26.0.0，门限设为 -70。
- 动作：开始扫描。
- 结果：新上报设备的 RSSI 大于等于 -70，或 RSSI 为无效值 127 时单独标为无效而不是当成强信号。
- 证据：列表 RSSI 列。

### NL-036 服务 UUID 不能作为系统过滤

- 前置：用户输入服务 UUID 希望系统只上报该 UUID。
- 动作：开始扫描。
- 结果：界面说明系统扫描过滤不包含服务 UUID，结果来自广播解析后的本地筛选。
- 证据：说明文案。本地筛选关闭时，不含该 UUID 的设备仍可出现。

### NL-037 扫描失败保留错误码

- 前置：启动扫描返回 `1009700003`、`1009700099` 或 801 之一。
- 动作：查看结果区。
- 结果：显示对应码和一句原因，列表保持上一次结果或空态，不显示成零台设备的成功扫描。
- 证据：错误码文本。

### NL-038 列表字段

- 前置：至少扫到一台设备。
- 动作：查看列表行。
- 结果：每行有地址、名称、RSSI、是否可连接、最近一次发现时间。`deviceClass` 在 5.1.0(18) 及以上有值时显示设备类型。
- 证据：行内容。

### NL-039 按地址合并更新

- 前置：同一随机地址连续上报。
- 动作：保持扫描。
- 结果：列表一行更新 RSSI 与发现次数，不无限追加重复行。
- 证据：发现次数大于 1 且行数不随回调线性增长。

### NL-040 扫描进行中可改过滤并重新开始

- 前置：正在扫描。
- 动作：修改过滤后确认。
- 结果：先停止旧扫描并取消订阅，再按新条件启动。旧条件的设备不再被标记为仍符合新过滤。
- 证据：停止日志后紧跟新的开始日志。

## 广播解析与身份

### NL-041 展示原始广播

- 前置：某次结果的 `data` 非空。
- 动作：打开广播详情。
- 结果：可见完整 HEX。
- 证据：HEX 与字节长度。

### NL-042 空广播

- 前置：`data` 长度为 0。
- 动作：打开广播详情。
- 结果：显示无广播数据，不显示解析成功。
- 证据：空数据文案。

### NL-043 解析完整本地名与缩短名

- 前置：广播含类型 `0x0B` 或 `0x0A`。
- 动作：打开详情。
- 结果：显示对应名称，并标明是完整名还是缩短名。
- 证据：类型与字符串。

### NL-044 名称字段与 0x0B 不一致

- 前置：`deviceName` 短于 `0x0B` 中的名称，或服务数据 TLV 把名称截成 9 字节。
- 动作：打开详情。
- 结果：两套名称同时可见，并说明系统上报名可能来自设备信息管理服务的本地名称 TLV。
- 证据：两段文本都在详情中。

### NL-045 用截断名过滤才能扫到

- 前置：已知完整名扫不到、前 9 个字符能扫到。
- 动作：查看该设备详情。
- 结果：详情写出服务数据中的名称长度，而不是只显示「扫描失败」。
- 证据：长度数值与原始 HEX。

### NL-046 服务数据与厂商数据

- 前置：广播含 `0x03` 或 `0x04`，以及 `0xFF`。
- 动作：打开详情。
- 结果：16 比特与 128 比特服务数据分列 UUID 和值；厂商数据分列厂商 ID 与 HEX。
- 证据：分列后的字段。

### NL-047 未知类型保留

- 前置：广播含指南未列出的类型。
- 动作：打开详情。
- 结果：该段以类型号和原始 HEX 保留，整包不被丢弃。
- 证据：未知类型行仍在。

### NL-048 16 比特标准 UUID 展开

- 前置：广播含 16 比特标准服务 UUID。
- 动作：查看展开后的 UUID。
- 结果：前 112 比特为 `37BEA880-FC70-11EA-B720-000000000000` 的对应前缀，后 16 比特为原值。不使用 `FFFFFFFF-1234-5678-ABCD` 占位前缀。
- 证据：展开字符串。

### NL-049 随机地址提示

- 前置：列表展示扫描地址。
- 动作：查看地址说明。
- 结果：标明这是随机地址，映射清除后可能变化。
- 证据：说明文案。

### NL-050 收藏不单靠地址

- 前置：用户收藏一台设备。
- 动作：保存收藏。
- 结果：记录至少包含名称、设备类型（若有）和最近地址。仅有地址时提示身份可能变化。
- 证据：收藏条目的字段。

### NL-051 已配对地址可从配对列表对照

- 前置：系统不低于 6.0.1(21)，设备已配对。
- 动作：打开已配对列表。
- 结果：显示 `getPairedDevices()` 返回的地址，并可与扫描行对照。
- 证据：地址列表。

### NL-052 低版本没有已配对列表接口

- 前置：系统低于 6.0.1(21)。
- 动作：打开已配对列表。
- 结果：显示该能力自 6.0.1(21) 起，不显示空列表当作「没有配对设备」。
- 证据：版本说明文案。

## 角色与广播

### NL-053 可连接广播

- 前置：已授权且星闪打开。用户确认发送可连接广播。
- 动作：开始广播。
- 结果：得到广播 ID，状态为已开始。日志含间隔、功率档和是否可连接。
- 证据：广播 ID。

### NL-054 停止指定广播

- 前置：已有广播 ID。
- 动作：停止。
- 结果：该 ID 变为已停止。
- 证据：停止成功日志。

### NL-055 广播间隔越界

- 前置：间隔小于 160 或大于 16777215 slot。
- 动作：开始广播。
- 结果：不启动，提示合法范围与默认 5000。
- 证据：校验文案。

### NL-056 广播数据可选字段

- 前置：用户只打开「包含本机名」，不填服务 UUID 和厂商数据。
- 动作：开始广播。
- 结果：可以启动。未填的服务与厂商字段不作为空数组强制塞入导致 401。
- 证据：成功日志。

### NL-057 手机之间的系统设置连接

- 前置：对端也是手机、平板或 PC/2in1。
- 动作：用户询问为何设置里配对后立刻断开。
- 结果：说明设置里的系统连接要求对端提供可用服务，两端都是中心设备时会断开；业务连接要由本模块发起 SSAP 或端口连接。
- 证据：说明文案。

### NL-058 端口没有客户端角色

- 前置：用户建立端口通道。
- 动作：查看角色标识。
- 结果：显示两端对等，任一端可发起连接。不把本端标成 SSAP 客户端。
- 证据：角色文案。

## SSAP 客户端

### NL-059 同一远端只建一次客户端

- 前置：已对地址 A 创建 Client。官方 SSAP 对 Client 与 Server 都写明：一个应用针对一个远端设备只需要创建一次实例。
- 动作：再次对 A 发起连接。
- 结果：复用已有 Client，不创建第二个实例。已打开的 Server 同样不再调用 `createServer`。
- 证据：日志中的创建次数为 1。

### NL-060 连接中的可见状态

- 前置：已调用 `connect` 且尚未收到已连接。
- 动作：查看会话。
- 结果：显示连接中、目标地址和已等待时间。
- 证据：连接中文案与耗时。

### NL-061 连接成功后发现服务

- 前置：`connectionStateChange` 为已连接。
- 动作：获取服务。
- 结果：列出每个服务的 UUID 和其 Property 的 UUID、operation 位、值摘要。
- 证据：服务树行。

### NL-062 未连接时禁止发现服务

- 前置：状态为已断开。
- 动作：点击发现服务。
- 结果：不调用 `getServices`，提示未连接。
- 证据：提示文案。

### NL-063 读属性

- 前置：已连接且 Property 的 operation 含可读。
- 动作：读取。
- 结果：展示返回值的 HEX，并在可按 UTF-8 解码时附文本。写一条入方向日志。
- 证据：HEX 与日志方向。

### NL-064 不可读属性

- 前置：operation 不含 `READABLE`。
- 动作：查看该属性。
- 结果：读入口不可用，并显示不支持读。
- 证据：入口禁用。

### NL-065 写有响应与无响应

- 前置：operation 同时含两种写。
- 动作：分别选择 `WRITE` 与 `WRITE_NO_RESPONSE` 写入合法 HEX。
- 结果：两次请求的写类型写入日志。无响应写不以「等待响应超时」记失败。
- 证据：日志中的写类型。

### NL-066 写类型与属性能力不符

- 前置：属性只有无响应写。
- 动作：用户选择有响应写。
- 结果：不允许发出，提示该属性不支持有响应写。
- 证据：未发送日志。

### NL-067 非法 HEX

- 前置：输入奇数位或非十六进制字符。
- 动作：写入。
- 结果：不发送，提示 HEX 不合法。
- 证据：校验文案。

### NL-068 通知五条件

- 前置：属性含 `NOTIFY`，且服务端描述符包含客户端属性配置。已连接并完成 `getServices`。
- 动作：打开通知并确认已订阅 `propertyChange`。
- 结果：对端更新后，本端出现通知记录。
- 证据：入方向通知日志。

### NL-069 未开通知则没有回调

- 前置：已连接并发现服务，但未调用 `setPropertyNotification(true)`。
- 动作：对端改变属性。
- 结果：本端不把静默当成链路故障；详情说明通知未启用。
- 证据：说明文案，且无该属性的通知日志。

### NL-070 断线后通知失效

- 前置：通知曾启用，随后连接变为已断开。
- 动作：再次连接成功。
- 结果：界面显示通知需重新启用。在用户再次启用前，不显示「通知仍有效」。
- 证据：重新启用提示。

### NL-071 MTU 请求范围

- 前置：已连接。
- 动作：请求 MTU 22、256 和 512。
- 结果：三次请求都被接受并订阅 `mtuChange`。日志同时有请求值与回调值。
- 证据：两条数值。

### NL-072 MTU 越界

- 前置：已连接。
- 动作：请求 21 或 513。
- 结果：不调用接口，提示 SSAP MTU 范围 [22, 512]。
- 证据：校验文案。

### NL-073 未连接时请求 MTU

- 前置：未连接。
- 动作：请求 MTU。
- 结果：不调用 `requestMtuSize`，提示需先连接。避免把 `1009700099` 当成唯一提示。
- 证据：未连接文案。

### NL-074 写入超过当前 MTU

- 前置：已有协商 MTU。
- 动作：提交更长的属性值。
- 结果：发送前提示超过当前 MTU，并让用户选择取消或按 MTU 切片。未选择前不发送。
- 证据：提示中的 MTU 数值。

### NL-075 断开后保留日志并可再连

- 前置：会话中已有读写日志，然后断开。
- 动作：查看会话并点击重连。
- 结果：旧日志仍在。重连再次调用已有 Client 的 `connect`。
- 证据：日志条数不减少，并出现新的连接中状态。

### NL-076 连接失败可见原因

- 前置：`connect` 失败或原因值为 `CONNECTION_FAILURE`。
- 动作：查看会话。
- 结果：显示失败，并带错误码。26.0.0 及以上若有 `reasonMsg`，只出现在日志详情，不参与分支判断。
- 证据：错误码文本。

## SSAP 服务端

### NL-077 添加服务后可被发现

- 前置：本端已 `addService`，属性 operation 含可读。对端用另一台真机扫描并连接。
- 动作：对端发现服务。
- 结果：对端能看到本端声明的服务 UUID。
- 证据：对端服务树含该 UUID。

### NL-078 读请求必须带请求 ID 回复

- 前置：收到 `propertyRead`。
- 动作：发送响应。
- 结果：响应携带该次 `requestId`。日志含请求 ID。
- 证据：日志中的 ID 与请求一致。

### NL-079 无通知位时不能宣称已通知

- 前置：属性 operation 不含 `NOTIFY`。
- 动作：点击通知对端。
- 结果：不调用 `notifyPropertyChanged`，提示属性未声明通知。
- 证据：提示文案。

### NL-116 有响应写请求要回复

- 前置：服务端已订阅 `propertyWrite`。本次 `PropertyWriteRequest.writeType` 为 `WRITE`。
- 动作：回复该次写请求。
- 结果：调用 `sendResponse`。响应里的 `requestId` 与本次请求相同，`address` 与请求地址相同。
- 证据：日志中的 `requestId` 与写请求一致。

### NL-117 无响应写不回复

- 前置：本次写请求的 `writeType` 为 `WRITE_NO_RESPONSE`。
- 动作：处理该次写请求。
- 结果：本地留下该次写入的值和写类型。不调用 `sendResponse`。
- 证据：日志含 `WRITE_NO_RESPONSE`，且没有该 `requestId` 的 `sendResponse` 记录。

### NL-118 向已连接客户端发通知

- 前置：属性 operation 含 `NOTIFY`，且已有客户端地址。
- 动作：向该地址发送属性更新。
- 结果：调用 `notifyPropertyChanged(address, property)`。成功后日志含该地址和 `propertyUuid`。
- 证据：成功日志中的地址与 UUID。

### NL-119 关闭服务端

- 前置：服务端实例仍处于打开状态。
- 动作：用户关闭服务端。
- 结果：调用 `Server.close()`。界面显示服务端已关闭。
- 证据：关闭成功日志。

### NL-120 删除已添加的服务

- 前置：该 `serviceUuid` 已通过 `addService` 添加。
- 动作：用户删除该服务。
- 结果：调用 `removeService(serviceUuid)`。本端服务列表不再包含该 UUID。
- 证据：列表与日志中的 UUID。

## 端口数传

### NL-080 两端 UUID 一致才能连接

- 前置：本端已 `createPort`。对端注册了不同 UUID。
- 动作：用本端 UUID 发起 `connect`。
- 结果：会话保持未建立，并提示两端 UUID 必须一致。不显示已连接。
- 证据：连接状态不是 `STATE_CONNECTED`。

### NL-081 注册后连接

- 前置：两端 UUID 相同且都已注册，星闪已打开。
- 动作：本端 `connect`。
- 结果：`connectionStateChanged` 变为已连接后，界面显示已连接和协商 MTU。
- 证据：状态与 `ConnectionResult.mtu`。

### NL-082 重复注册同一 UUID

- 前置：UUID 已注册。
- 动作：再次 `createPort`。
- 结果：显示 `1009700020`，并提供销毁后重试。
- 证据：错误码。

### NL-083 端口数量超限

- 前置：继续注册直到返回 `1009700021`。
- 动作：查看提示。
- 结果：提示销毁其他端口。不显示具体个数上限。
- 证据：错误码文案。

### NL-084 销毁未注册 UUID

- 前置：目标 UUID 从未注册。
- 动作：销毁。
- 结果：显示 `1009700022`。
- 证据：错误码。

### NL-085 文本与 HEX 发送

- 前置：端口已连接。
- 动作：发送一段文本，再发送偶数位 HEX。
- 结果：两条出方向日志分别标明文本或 HEX，以及字节数。
- 证据：日志字段。

### NL-086 接收数据

- 前置：已订阅 `readData`，对端写入。
- 动作：查看终端。
- 结果：出现入方向记录，含地址、UUID 和 HEX。
- 证据：入方向日志。

### NL-087 超过协商 MTU 的发送

- 前置：已知 `ConnectionResult.mtu`。
- 动作：提交更长载荷。
- 结果：发送前提示超过端口 MTU。用户未确认切片前不调用 `writeData`。
- 证据：提示中的 MTU。

### NL-088 端口 MTU 默认与范围

- 前置：用户不填 MTU。
- 动作：发起连接。
- 结果：请求按默认 512 发出。用户若填写，只接受 [0, 65535]。这与 SSAP 的 [22, 512] 分开展示。
- 证据：连接参数日志中的 MTU 与通道类型。

### NL-089 可靠模式与基础模式

- 前置：连接参数可选 `BASIC` 或 `RELIABLE`。
- 动作：分别建立两次会话。
- 结果：界面写明基础模式无重传、可靠模式有重传。默认是基础模式。
- 证据：模式文案。

### NL-090 拥塞

- 前置：连续 `writeData` 导致 `1009700023`。
- 动作：查看终端。
- 结果：显示拥塞，停止连发，后续自动间隔至少 10ms。每次拥塞写错误日志。
- 证据：错误码与间隔后的下一次发送时间。

### NL-091 断开端口

- 前置：端口已连接。
- 动作：断开。
- 结果：状态变为已断开，接收订阅仍可在重连前取消，避免重复订阅。
- 证据：断开日志。

### NL-092 离开会话销毁或明确保持

- 前置：本会话注册了端口。
- 动作：用户关闭会话并选择释放。
- 结果：调用 `destroyPort`。若用户选择保持，界面仍显示该 UUID 占用。
- 证据：销毁日志或占用列表。

- 动作：发送端口数据。

### NL-099 配对失败原因

### NL-100 低版本无配对发起接口时的提示

## 吞吐、重连、日志与诊断

### NL-102 应用层收发计数

- 前置：端口会话已收发多包。
- 动作：查看统计。
- 结果：显示发送字节、接收字节、包数。标注这是应用层计数，不是空口速率。
- 证据：统计文案含「应用层」。

### NL-103 不提供 PHY 与连接后 RSSI

- 前置：用户打开链路诊断。
- 动作：查找 PHY、连接间隔、对端 RSSI。
- 结果：这三项显示为 Kit 未提供。扫描阶段的 RSSI 仍只出现在扫描行。
- 证据：缺口文案，扫描行 RSSI 仍在。

### NL-104 无效 RSSI

- 前置：扫描 RSSI 为 127。
- 动作：查看该行。
- 结果：显示无效，不参与「信号强」排序，也不当成 127 dBm 的真实强度。
- 证据：无效标记。

### NL-105 手动重连

- 前置：SSAP 或端口已断开。
- 动作：点击重连。
- 结果：使用当前地址重新连接。没有「系统将自动重连」的文案。
- 证据：新的连接中日志由用户点击触发。

### NL-106 重连使用当前扫描地址

- 前置：收藏中的旧地址与新扫描地址不同。
- 动作：从新扫描结果连接。
- 结果：连接参数使用新地址，并提示旧地址可能已失效。
- 证据：连接日志中的地址等于新扫描地址。

### NL-107 统一日志含错误码

- 前置：发生 201、401、801、`1009700003` 或 `1009700023` 之一。
- 动作：打开本会话日志。
- 结果：记录时间、方向或内部类型、错误码、接口名。
- 证据：日志行字段。

### NL-108 权限结果写入日志

- 前置：用户同意或拒绝星闪权限。
- 动作：查看日志。
- 结果：有一条权限结果，不记录权限弹窗以外的个人信息。
- 证据：权限日志类型。

### NL-109 导出包含广播 HEX

- 前置：会话中有扫描详情。
- 动作：导出该会话。
- 结果：导出内容含原始广播 HEX 与解析字段。导出失败时会话数据仍留在页面。
- 证据：导出文本中的 HEX。

### NL-110 扫描离开即停

- 前置：扫描进行中，应用进入后台。
- 动作：等待系统可能挂起应用。
- 结果：扫描被停止。回到前台后显示已停止，需用户再次开始。
- 证据：停止日志。官方未提供后台扫描接口，本条不要求后台继续发现设备。

## 与蓝牙并存时的边界

### NL-111 星闪关闭不等于蓝牙关闭

- 前置：蓝牙打开、星闪关闭。
- 动作：查看星闪模块状态。
- 结果：星闪显示关闭。不因为蓝牙已打开而显示星闪可用。
- 证据：星闪状态文案。

### NL-112 设置路径按文案说明

- 前置：需要用户打开星闪。
- 动作：查看引导。
- 结果：同时写明「设置 > 多设备协同 > 星闪」以及部分版本的「设置 > 星闪和蓝牙 > 星闪」。
- 证据：两段路径文案。

### NL-113 蓝牙 HCI 日志不代表星闪抓包

- 前置：用户要求抓取星闪空口。
- 动作：打开诊断说明。
- 结果：说明开发者选项中的 HCI 日志是蓝牙日志，Release 还会去掉载荷；本模块不能提供星闪空口帧。
- 证据：说明文案。

### NL-114 MTU 失败不混用蓝牙码

- 前置：星闪 `requestMtuSize` 失败返回 `1009700099`。
- 动作：查看错误。
- 结果：显示星闪错误码。不把蓝牙 `2900099` 写进这条记录。
- 证据：日志中的码。

### NL-115 合作设备集不是调试前提

- 前置：`1009700050` 或设备无 CDSM。
- 动作：使用扫描和 SSAP。
- 结果：扫描与 SSAP 仍可按自身前提使用。CDSM 页显示本设备不支持合作设备集。
- 证据：CDSM 缺口文案，扫描仍可启动。

## 覆盖摘要

三条集合互斥，每条只归入一处。

### 可验收实现

NL-002、NL-004–NL-022、NL-025–NL-033、NL-037–NL-050、NL-053–NL-075、NL-077–NL-096、NL-098、NL-099、NL-102、NL-104–NL-112、NL-114、NL-116–NL-120。

NL-105 归在这里：通过标准是用户点击后用当前地址重新连接。系统自动重连不是这条的目标。

NL-110 归在这里：没有后台扫描 API，进入后台后停止扫描是必须做到的行为。回到前台显示已停止，并由用户再次开始。

### 版本门槛

达到起始版本才调用对应接口。低于该版本时显示起始版本，并且不调用该接口。

NL-001、NL-003、NL-023、NL-024、NL-034、NL-035、NL-051、NL-052、NL-076、NL-097、NL-100。

### 必须标明的缺口

通过标准是界面写明 Kit 未提供该能力，并且不出现该能力的成功态。

NL-036、NL-101、NL-103、NL-113、NL-115。

NL-105 与 NL-110 不在本集合。
